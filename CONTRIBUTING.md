# Contributing

Thanks for helping. A false positive is the most useful report you can send: attach the model, or
say how to make one like it. A few things make a pull request easy to merge:

- **Open an issue first** for anything larger than a small fix, so we can agree on the shape.
- **One change per pull request**, with a short description of what and why, and how you tested it.
- **Tests** come with every new feature and every bug fix.
- **Checks** must pass (CI runs the same):

  ```sh
  cargo fmt --all --check
  cargo clippy --workspace --all-targets -- -D warnings
  cargo test --workspace
  cargo deny check
  ```

- **gltfpack**: the `meshdiet fix` tests run the real gltfpack 1.3, found through
  `MESHDIET_TEST_GLTFPACK` or `PATH`. Without it they print a skip line and pass, so install it when
  you work on `fix`:

  ```sh
  MESHDIET_TEST_GLTFPACK=$(command -v gltfpack) cargo test --workspace
  ```

  `scripts/smoke.sh target/debug/meshdiet [path/to/gltfpack]` runs a built binary against the demo
  site the way a user would.

- **A new rule** needs a `tests/fixtures/<RULE-ID>/bad` folder that shows the problem (with an
  `expected.json`) and a `good` one that must stay quiet. Every model there is generated by code:
  edit `xtask/src/fixtures.rs`, run `cargo xtask gen-fixtures` and commit both. Never commit a
  third-party or downloaded model. Details in [tests/fixtures/README.md](tests/fixtures/README.md).
- **CHANGELOG.md**: add a line under *Unreleased*, written for people who use meshdiet.
- Be kind.

project.
